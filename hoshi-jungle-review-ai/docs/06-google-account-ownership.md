# 06. どの Google アカウントを使うか（重要）

このシステムには **Google が 2 回登場します。** この 2 つは別物で、
所有者を分けることも、揃えることもできます。混同すると後から直すのが面倒なので、
着手前に決めてください。

| # | 何を作るか | 何のためか | 誰のアカウントで作る？ |
|---|---|---|---|
| ① | **Google Cloud プロジェクト**<br/>（OAuth クライアント ID / シークレット） | アプリが Google API を呼ぶための「開発者側の登録」 | 開発・保守する側（Suzu）でも、ホテル側でもよい |
| ② | **アプリにログインする Google アカウント** | ホテルのクチコミを取得し、返信を投稿する権限そのもの | **必ず Hoshi Jungle のアカウント** |

---

## ② が Hoshi Jungle のアカウントでなければならない理由

アプリにログインしたアカウントの `refresh_token` が暗号化されて DB に保存され、
**以降すべてのクチコミ取得と返信投稿が、そのアカウントの権限で実行されます。**

もし Suzu 個人のアカウントでログインすると、次の問題が起きます。

- **Google 上の返信者が Suzu 個人の権限で動く。** ホテルの資産であるべき運用が個人に紐づく
- Suzu が Hoshi Jungle のビジネスプロフィールへのアクセス権を失った時点で、
  **システム全体が停止する**（クチコミ取得も返信も不能になる）
- 契約終了時の引き継ぎに、アカウント権限の移譲作業が必要になる
- 万一 Suzu のアカウントが侵害されると、ホテルのビジネスプロフィールまで危険にさらされる

Hoshi Jungle のアカウントでログインしておけば、
**ホテル側が自分の資産としてシステムを保持でき、担当者が誰であっても運用が続きます。**

### 必要な条件

ログインに使う Hoshi Jungle の Google アカウントは、
**Hoshi Jungle の Google ビジネスプロフィールに対してオーナーまたは管理者**である必要があります。

確認方法: [business.google.com](https://business.google.com) にそのアカウントでログインし、
Hoshi Jungle のプロフィールが管理対象として表示されればOKです。
表示されない場合は、現在のオーナーから「管理者」として招待してもらってください。

> 権限がないアカウントでログインすると、初期設定ウィザードの
> ロケーション一覧が **0 件** になります。エラーではなく「管理対象がない」状態です。

---

## ① はどちらでもよい（ただし決めておく）

Google Cloud プロジェクトは、OAuth クライアント ID とシークレットを発行する入れ物です。
アプリの「開発者登録」にあたるもので、ホテルのデータには直接触れません。

| 選択肢 | 向いているケース | 注意点 |
|---|---|---|
| **Suzu のアカウントで作る** | Suzu が開発・保守を継続する。他のホテルにも横展開する予定がある | 契約終了時にクライアント ID をホテルへ移す作業が必要。API アクセス申請もSuzu名義 |
| **Hoshi Jungle のアカウントで作る** | ホテル側が完全に自立して保有したい | Google Cloud Console の操作をホテル側に依頼する必要がある。API 申請もホテル名義 |

**推奨: Hoshi Jungle のアカウントで作る。**
Google の API アクセス申請は「どのビジネスのために使うか」を審査されるため、
実際にビジネスを運営している主体の名義で出したほうが承認されやすく、
引き渡しも一度で完結します。Suzu は Hoshi Jungle のアカウントに
「編集者」として招待してもらえば、設定作業は問題なく代行できます。

## スタッフは Google アカウント不要

ここまでの話は**オーナー（1 人）だけ**の話です。
フロントスタッフは Google アカウントを一切使いません。
配布されたパスコードだけで入室します（[docs/05](05-staff-access.md)）。

```
オーナー（Hoshi Jungle のGoogleアカウント） … 1人。連携とパスコード発行
スタッフ（Googleアカウント不要）            … 何人でも。パスコードで入室
```

## 決定事項（本プロジェクト）

| 項目 | 決定 |
|---|---|
| アプリにログインするアカウント（②） | **Hoshi Jungle のアカウント**（ホテル側に確認中） |
| 設定作業を代行する側のアカウント | **`leavesbali@gmail.com`**（Leaves Bali 業務用） |

代行する場合、Hoshi Jungle 側で `leavesbali@gmail.com` を
**ビジネスプロフィールの「管理者」として追加**していただく必要があります。
[business.google.com](https://business.google.com) → ユーザー → ユーザーを追加。

これは Google 公式の権限付与機能であり、パスワードの共有は不要です。
ホテル側の操作でいつでも解除できます。

> 代行アカウントを追加しても、**アプリにログインするのは Hoshi Jungle のアカウント**です。
> 代行アカウントはあくまで設定作業のためのもので、システムの稼働はホテル側の
> アカウントに紐づきます（この分離が引き継ぎを容易にします）。

## 作業を始める前のチェックリスト

- [ ] Hoshi Jungle の Google アカウントを特定した（誰が管理しているか）
- [ ] そのアカウントがビジネスプロフィールのオーナー/管理者であることを確認した
- [ ] Google Cloud プロジェクトを①どちらの名義で作るか決めた
- [ ] OAuth 同意画面の「テストユーザー」に、ログインに使う Hoshi Jungle の
      アカウントを登録した（アプリを公開審査に出さない場合に必須）
